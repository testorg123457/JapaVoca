# 이슈 자동구현 파이프라인 — 사용자 1회 설정

> 이슈에 `claude` 라벨만 달면 Claude가 구현·PR·기계적 리뷰수정을 자동으로 하고,
> 너는 "구현 방향"만 확인하고 머지하는 파이프라인. 워크플로우 파일은 이미 저장소에 있음
> (`.github/workflows/`). 아래 4가지만 **관리자 권한으로 1회** 설정하면 작동한다.

## 1. 구독 OAuth 토큰 발급 → Secret 등록

터미널에서:
```bash
claude setup-token
```
출력된 토큰을 복사한 뒤, GitHub 저장소에서:
`Settings → Secrets and variables → Actions → New repository secret`
- Name: `CLAUDE_CODE_OAUTH_TOKEN`
- Value: 복사한 토큰

## 2. Claude GitHub App 설치

`https://github.com/apps/claude` → Install → `testorg123457/JapaVoca` 선택.

> ⚠️ 안 하면: (a) Claude가 브랜치/PR을 push 못 하고, (b) Claude가 만든 PR·커밋에
> CI·리뷰 워크플로우가 **트리거되지 않는다**(기본 GITHUB_TOKEN 제약). 반드시 설치.

## 3. `claude` 라벨 생성

저장소 `Issues → Labels → New label` → 이름 정확히 `claude`.

## 4. main 브랜치 보호 규칙

`Settings → Branches → Add branch protection rule` (target: `main`):
- ✅ Require a pull request before merging → Require **1** approving review
- ✅ Require status checks to pass before merging → 검색해서 **`mobile`**, **`server`** 추가
  (`ci.yml`의 두 job. PR이 한 번 돌고 나면 목록에 뜬다.)
- 리뷰 워크플로우(`Claude Review`)는 **required에 넣지 않는다** — 자문·자동수정용이라 머지를 막지 않음.

---

## 사용법

1. 이슈를 작성한다 (원하는 기능/버그를 설명. 자세할수록 좋음).
2. 그 이슈에 **`claude` 라벨**을 단다.
3. 잠시 뒤 `claude/issue-<번호>` 브랜치와 PR이 자동 생성된다.
   - PR 본문의 **"구현 요약"** 을 읽고 *구현 방향이 의도대로인지* 확인한다.
   - 버그·코드 퀄리티는 리뷰 워크플로우가 알아서 고쳐 커밋한다(신경 안 써도 됨).
4. 방향을 바꾸고 싶으면 PR에 `@claude ...` 코멘트로 지시 → 같은 PR에 반영.
5. **CI(mobile·server) ✅ + 네 승인** 후 **Merge** 버튼 클릭. (유일한 수동 단계)

## 동작 요약

| 워크플로우 | 트리거 | 하는 일 |
|---|---|---|
| `claude-implement.yml` | 이슈에 `claude` 라벨 | 구현 → 브랜치 → PR(+구현 요약) |
| `ci.yml` | PR open/update | mobile(tsc·lint·jest) + server(migrate·test) |
| `claude-review.yml` | PR open/update | 버그·퀄리티·CLAUDE.md 위반 자동 수정 커밋 |
