## B. 콘텐츠 데이터

시드 데이터 쪽으로 분류했었는데, 3건 중 2건은 코드 문제였다(아래 참고).

- [ ] "모자랄 결(缺)" 한자에 구성자로 "하품 흠(欠)"이 있는데, 구성 자세히 보기 들어가면 없음
      ↳ 缺은 `tbl_content_kanji`에 행 자체가 없다(2,205자에 미포함). 구성 트리 API가 404를 주고
        화면엔 "구성 정보를 불러오지 못했어요"가 뜬다. 시드 데이터 추가 필요.
        ⚠️ 별개로 `_parse_component_pairs`는 `글자(뜻)` 꼴이 아닌 조각을 조용히 버리므로,
        데이터를 넣을 때 괄호 포맷을 지켜야 한다.
- [x] "길 도(道)"가 "미치"도 되는 거 아님? 그냥 듣기 했는데 "도우" 하고 끝, "물고기(魚)"도 "으오" 이러고 끝남
      ↳ 데이터가 아니라 코드였다. 훈독은 페이로드에 실려 오는데 화면이 `on_reading`만 봤다.
        발음 소스를 훈독 우선(없으면 음독 폴백)으로 뒤집음. 이제 道=みち, 魚=うお·さかな.
- [x] 단어면 발음(히라가나/가타카나)도 보여줘야지
      ↳ 서버가 단어의 `on_reading`을 늘 빈 값으로 내려서 `!!detail.on_reading` 조건이 막고 있었다.
        `readingLine()`이 단어면 `word.reading`으로 떨어지게 함.

## C. 상자 / 캐시 루프

돈 루프가 막히는 영역이라 A 다음 우선순위.

- [x] 상자 터치 안 됨. 위쪽 눌러야 열림 → 터치 범위를 크게 늘려
      ↳ 탭 영역을 그림과 분리해 아래로 크게(면적 약 2.4배) 넓히고, 안드로이드가 부모 밖 터치를 안 주므로 무대 높이도 함께 키움(음수 marginBottom으로 상쇄). Lottie는 pointerEvents 제거해 판정에서 뺌.
- [x] 상자 눌렀는데 갑자기 화면 멈춤. 나갔다 들어와야 열림
      ↳ 원인 2개. ① 개봉 요청에 타임아웃이 없어 응답이 안 오면 phase가 'opening'에 갇힘 → 15초 상한. ② mountedRef를 마운트 시 true로 안 되돌려 Fast Refresh 후 응답을 무시함 → 수정. 광고 콜백이 안 오는 경우는 미해결(아래 메모).
- [x] 상자 위치 좀 아래로 내려
      ↳ transform translateY 6px(레이아웃이 아니라 transform이라 탭 영역도 같이 내려감).
- [x] 상자 여는 도중에 나가면, 다시 들어왔을 때 그 상자가 그대로 있고 누르면 "이미 개봉된 상자예요"
      ↳ 서버 로그에 그대로 남아 있던 버그(`POST boxes/63/open → 200` … 재시도 `→ 409`).
        응답 처리 맨 앞의 `if (!mountedRef.current) return`이 **갱신 예약(`pendingRefreshRef`)
        자체를 못 하게** 막고 있었다. 그래서 서버는 열고 캐시도 지급했는데 `['boxes','unopened']`가
        한 번도 무효화되지 않아 홈에 **유령 상자**가 남았다.
        화면이 사라진 건 갱신을 건너뛸 이유가 아니라 **더 급히 흘릴 이유**다(미룰 애니메이션이 없으므로).
        판단을 `screens/quiz/boxOpenRefresh.ts`(순수함수)로 빼고 성공·409·실패 **모든 경로에서**
        갱신하도록 수정. 회귀 테스트 5개.
      ↳ **그 아래 설계 문제도 같이 처리.** 진짜 원인은 *개봉(서버가 돈을 지급하는 트랜잭션)* 과
        *공개(상자 터지는 연출)* 를 하나로 묶어둔 것. 서버는 요청이 닿은 순간 끝났는데 사용자는
        아직 시작도 안 했다고 느낀다. 그 사이 나가면 돈은 받고 **뭘 받았는지는 모른 채** 상자만 사라진다.
        → **개봉 중(약 1초)엔 아예 못 나가게 잠갔다.** 확인 시트도 만들어봤지만 1초짜리 구간에
        모달을 세우는 건 과했다(사용자 판단). X는 자리를 두고 흐리게(opacity 0.35)만 — 사라지면
        상단이 들썩인다. ⚠️ X 버튼만 막으면 하드웨어 뒤로가기·엣지 스와이프로 빠져나가므로
        `beforeRemove`로 모든 이탈 경로를 받는다. 갇히지 않는 근거: 개봉 요청 15초 상한이 있고
        타임아웃이면 phase가 풀리며 자동으로 홈으로 나간다. 광고 시청 중엔 phase가 아직 'sealed'라
        X가 정상 동작한다(광고는 길 수 있으므로).
        (더 나은 해법은 `viewed_at`을 둬 개봉과 공개를 분리하는 것 — 서버 마이그레이션 필요해 보류.)
- [x] 뒤로가기 눌렀는데 상자페이지 가짐
      ↳ 잠금화면 퀴즈의 상자 뱃지에 연타 방지가 없어 개봉 화면이 스택에 두 번 쌓였다. 홈과 같은 방식(navLock + 화면 복귀 시 해제)으로 막음

## D. 퀴즈 반응성·피드백

- [x] 정답 눌렀을 때 반응이 즉각적이지 않음
      ↳ `await submitAnswer()` 뒤에 reveal로 넘어가서 정답 표시·효과음·상자 뱃지가 전부 왕복 시간만큼
        밀렸다. 정답키(`answer_index`)가 오프라인 채점용으로 이미 페이로드에 있으니 그걸로 즉시
        판정해 화면을 넘기고, 서버 응답으로 뒤에서 보정한다(`patchReveal`).
        앞당긴 건 *표시*뿐 — 상자 지급·캐시 적립은 그대로 서버 권위이고 응답이 온 뒤에만 뱃지를 띄운다.
        ⚠️ 이 과정에서 상자 뱃지 애니메이션 effect가 `[]` 의존성이라 뒤늦게 온 `boxGrade`를 놓쳐
        뱃지가 영영 안 보이는 문제를 같이 고쳤다(별도 effect로 분리).
        서버가 토큰을 거부(400)하면 결과를 걷어내지 않고 '다음'에서 세트를 재조회하도록 예약 —
        결과를 보다가 화면이 튀지 않게.
- [x] 정답 맞췄을 때 / 틀렸을 때 소리가 났으면 좋겠음
      ↳ react-native-audio-api로 정답·오답 효과음. 설정에 끄기 토글 추가(기기 설정, MMKV). ⚠️ 네이티브 의존성이라 리빌드 필요.
- [x] 한자 단어 두 글자랑 세 글자랑 크기 차이가 엄청남
      ↳ 카드마다 제 글자 수로 크기를 정하던 걸 폐기. 네 선택지가 '가장 긴 것' 기준 한 크기를 공유하고, 2~4글자는 26으로 통일·계단은 2px로 완만하게.

## F. 디자인

- [x] 캐시 내역 디자인
      ↳ **통장(passbook) 모델**로 다시 짬. 행마다 있던 초록/빨강 원형 아이콘 제거(8가지 사유는
        글자가 빠르고, 색 원이 매 줄 반복되면 색이 의미를 잃는다 — 원칙 §2). 적립·사용은
        **부호 + 금액 색**만으로. 오른쪽에 금액(17 Bold) 아래 **거래 후 잔액**(`balance_after`,
        서버가 이미 행마다 들고 있던 값)을 세워 숫자 열을 화면의 척추로 삼음.
        상단 요약에 누적 `total_earned`/`total_used` 인라인 통계 추가(카드 없이 헤어라인).
