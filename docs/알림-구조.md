# 알림 구조

알림은 성격이 다른 3가지가 있다.

| | ① 로컬 알림 | ② 인앱 알림함 | ③ 서버 푸시(FCM) |
|---|---|---|---|
| 만드는 주체 | 기기(네이티브) | 서버 | 서버 → FCM → 기기 |
| 보이는 곳 | 상단 알림바 | 앱 안 '알림' 화면 | 상단 알림바 |
| 앱 꺼도 뜨나 | ✅ | ❌ | ✅ |
| 상태 | 동작 중 | 동작 중 | **미구현(stub)** |

---

## ① 로컬 알림

`apps/mobile/android/.../` — 상시 고정(포그라운드 서비스). 이벤트마다 뜨는 게 아니라 항상 떠 있다.

| 서비스 | 채널 / ID | 문구 |
|---|---|---|
| `StudyNotificationService.kt` | `study_reminder` / 5151 | **일본어 한자 보카**<br>지금 일본어 단어를 공부해봐요! 📖 |
| `LockScreenService.kt` | `lock_learning` / 4242 | **잠금화면 학습 켜짐**<br>화면을 켤 때 일본어 퀴즈가 나와요 |

---

## ② 인앱 알림함

`Notification` 모델. 타입 8종 중 **5종만 실제로 생성된다.**

| 타입 | 알림 | 만드는 곳 |
|---|---|---|
| `streak` | 출석 7번 달성! / 보상을 받았어요 | `rewards/services.py` `check_in()` |
| `exchange` | 기프티콘 교환 완료 / 교환 실패(환불) | `exchange/views.py` |
| `referral` | 친구 초대 보상 N 캐시! / (상한 소진 시) 친구가 내 코드를 입력했어요 | `rewards/services.py` `redeem_referral()` |
| `system` | 운영자 공지 — Admin에서 발송 | `notifications/admin.py` 공지 발송 |
| `inquiry` | 문의에 답변이 등록됐어요 | `support/admin.py` 답변 저장 시 |
| `attendance` | — | ❌ 안 씀(매일 뜨는 '출석 완료'는 정보가 없어 제거) |
| `box` | — | ❌ 정의만 있고 안 만듦 |
| `quiz_reminder` | — | ❌ 정의만 있고 안 만듦 |

**알림이 안 가는 이벤트**: 캐시상자 획득·개봉, 퀴즈 마일스톤 보너스, 광고 보상.

화면에 들어오면 **자동으로 전부 읽음 처리**된다(홈 뱃지가 비워짐).
단 이번 방문에서 새로 본 알림에는 점을 계속 표시한다 — 눈앞에서 점이 사라지면
무엇이 새 알림이었는지 알 수 없기 때문.

### 시스템 공지 보내는 법

Django Admin **`/admin/notifications/notification/` → 우측 상단 "공지 발송"**.
제목·내용·이동할 화면·게스트 제외 여부를 정하고, **미리보기로 대상 수를 확인한 뒤** 발송한다.
(되돌릴 수 없어서 2단계로 나눠 뒀다.)

서버 콘솔에서 쓰려면: `python manage.py broadcast "제목" "내용" --screen Home --dry-run`

## ③ 서버 푸시 (FCM)

`notifications/push.py`의 `send_push()`가 stub — 로그만 남기고 항상 `False`.
`FCM_ENABLED=false`. `PushToken` 등록은 동작하므로 **Firebase 크리덴셜 + `firebase-admin` + `FcmProvider`만 채우면 된다.**
