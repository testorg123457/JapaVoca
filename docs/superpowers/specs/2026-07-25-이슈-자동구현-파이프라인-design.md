# 이슈 → PR → 리뷰 → 머지 자동화 파이프라인 — 설계

> 작성일 2026-07-25. 대상 저장소 `testorg123457/JapaVoca` (모노레포: `apps/mobile` RN, `apps/server` Django).

## 1. 목표

사용자가 **GitHub 이슈만 작성**하면, Claude가 알아서 구현하고 PR을 열고, 코드 품질은 자동으로 다듬고, 사용자는 **"구현 방향이 의도대로인가"만 확인한 뒤 머지 버튼을 누르는** 흐름을 만든다.

핵심 원칙: **사람의 유일한 수동 단계는 최종 머지 클릭.** 그 외(구현·PR 생성·버그/퀄리티 수정·CI)는 자동.

## 2. 확정된 결정

| 항목 | 결정 |
|---|---|
| 머지 게이트 | **사람 최종 승인** (자동 머지 안 함) |
| 트리거 | 이슈에 **`claude` 라벨** 부착 시 시작 |
| 인증/과금 | **구독 OAuth 토큰** (`claude setup-token` → Secret `CLAUDE_CODE_OAUTH_TOKEN`). 별도 API 과금 없음 |
| CI 범위 | **모바일 + 서버 둘 다** (mobile: tsc/eslint/jest, server: Postgres 컨테이너 + Django test) |
| 코드리뷰 — 기계적(버그·퀄리티) | **완전 자동 수정 루프** (Claude가 찾고 직접 고쳐 커밋) |
| 코드리뷰 — 접근/방향 | **사람이 판단** (PR "구현 요약"을 읽고 머지/재지시/닫기) |
| 리뷰 머지 게이트 | **자문만** (리뷰가 머지를 막지 않음. CI 통과 + 사람 클릭이 유일한 관문) |

## 3. 전체 플로우

```
① 사용자: 이슈 작성 + 'claude' 라벨
        │
        ▼
② [A] claude-implement.yml
   Claude가 이슈 읽음 → CLAUDE.md 규칙 따라 구현
   → 브랜치 claude/issue-<번호> → PR 생성
   → PR 본문에 "구현 요약"(접근·설계결정·건드린 구조·트레이드오프) 작성
        │
        ├──────────────┐
        ▼              ▼
③ [B] ci.yml        ④ [C] claude-review.yml (기계적 리뷰 = 1층)
   mobile 검사          diff에서 버그·퀄리티·CLAUDE.md 위반 탐지
   server 검사          → 직접 수정 커밋 → (synchronize로 CI·리뷰 재실행)
                        → 깨끗해지면 멈춤
        │
        ▼
⑤ 사용자: PR "구현 요약"(2층) 읽고 방향 판단
   - 방향 OK & CI ✅  → 머지 클릭  ← 유일한 수동 단계
   - 방향 수정 필요    → PR에 @claude 코멘트로 재지시
   - 접근 틀림        → PR 닫고 이슈 재정리
```

## 4. 구성 요소

### 4.1 워크플로우 A — `claude-implement.yml` (구현)

- 트리거: `on: issues: types: [labeled]`, 조건 `if: github.event.label.name == 'claude'`
- 권한: `contents: write`, `issues: write`, `pull-requests: write`
- 스텝: `actions/checkout` → `anthropics/claude-code-action@v1`
  - `claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}`
  - `prompt`: 이슈 제목/본문을 바탕으로 구현하고, **새 브랜치 `claude/issue-<번호>`에 커밋 후 PR을 열되, PR 본문에 "구현 요약" 섹션(접근/핵심 설계 결정/건드린 파일 구조/트레이드오프)을 반드시 포함**하라고 지시.
  - `claude_args`: `--max-turns` 상한(예: 30)으로 폭주 방지.
- 산출물: `claude/issue-<번호>` 브랜치 + 초안 아님(일반) PR.

### 4.2 워크플로우 B — `ci.yml` (머지 전 필수 검사)

- 트리거: `on: pull_request: [opened, synchronize, reopened]`
- job `mobile` (경로 `apps/mobile`):
  - `actions/setup-node`(레포 Node 버전) → `npm ci` → `npx tsc --noEmit` → `npm run lint` → `npm test`
  - 테스트는 `apps/mobile/__tests__/`에 18개 존재. eslint 설정 `.eslintrc.js` 존재.
- job `server` (경로 `apps/server`):
  - `services: postgres`(공식 postgres 이미지) 컨테이너 기동, healthcheck 대기.
  - Python 3.13 setup → `pip install -r requirements.txt`
  - 환경변수: `DATABASE_URL=postgres://postgres:postgres@localhost:5432/postgres`, `DB_SSLMODE=disable`, `SECRET_KEY`(임의), `DEBUG=False`.
  - `python manage.py migrate` → `python manage.py test --noinput` (CI Postgres는 전용이라 `--keepdb` 불필요).

### 4.3 워크플로우 C — `claude-review.yml` (기계적 리뷰 = 1층, 자동 수정)

- 트리거: `on: pull_request: [opened, synchronize]`
- **무한루프 가드**: 마지막 커밋 author가 봇(Claude/App)이면 스킵. `concurrency` 그룹으로 PR당 1개만 실행.
- 스텝: `actions/checkout` → `anthropics/claude-code-action@v1`
  - `claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}`
  - `prompt`: 이 PR의 diff를 **버그·코드 퀄리티·CLAUDE.md 규칙 위반(캐시 정합성 원장/잔액 트랜잭션, 토큰 하드코딩 금지, 이모지 기능아이콘 금지 등)** 기준으로 검토하고, **발견한 문제를 직접 고쳐 같은 브랜치에 커밋**하라고 지시. 접근/방향은 건드리지 말 것(그건 사람 몫).
  - `claude_args`: `--max-turns` 상한.
- 효과: 수정 커밋이 push되면 `synchronize`로 B(CI)와 C가 재실행 → 더 고칠 게 없으면 C는 무커밋으로 종료(자연 수렴).

### 4.4 main 브랜치 보호 규칙 (사람 승인 게이트를 실제로 만드는 부분)

- 필수 상태 검사(required status checks): `ci.yml`의 `mobile`, `server` job 통과.
- 필수 승인 리뷰(required approving review): 1개 (= 사용자 승인). → CI 통과 + 사용자 승인 전엔 머지 버튼 비활성.
- (리뷰 워크플로우 C는 필수 검사에 **넣지 않음** → 자문만, 머지 안 막음.)

## 5. 기존 코드 손봐야 할 것 (파이프라인 전제)

### 5.1 `apps/server/config/settings.py` — sslmode 파라미터화 (필수)

현재 DB `OPTIONS`에 `'sslmode': 'require'`가 **하드코딩**되어 있어, CI의 평문 Postgres 컨테이너(SSL 미지원)엔 연결 실패.

- 변경: `sslmode`를 `DB_SSLMODE` 환경변수로 뺀다. **기본값 `require` 유지**(프로덕션/Supabase 무영향), CI에서만 `DB_SSLMODE=disable`.
- 영향 범위: 최소. 프로덕션 동작 불변.

### 5.2 Claude GitHub App 설치 (필수)

- 안 하면: (a) Claude가 브랜치/PR을 push 못 함, (b) Claude가 만든 PR/커밋에 CI·리뷰 워크플로우가 **트리거되지 않음**(기본 `GITHUB_TOKEN`으로 만든 커밋은 다른 워크플로우를 못 깨움).
- App 설치로 두 문제 모두 해결. 설치 위치: `https://github.com/apps/claude` → `testorg123457/JapaVoca`.

## 6. 사용자가 1회 준비할 것 (관리자 권한 필요)

1. `claude setup-token` 실행 → 출력 토큰을 GitHub Secret **`CLAUDE_CODE_OAUTH_TOKEN`** 으로 등록 (Settings → Secrets and variables → Actions).
2. Claude GitHub App을 `testorg123457/JapaVoca`에 설치.
3. `claude` 라벨 생성 (없으면).
4. main 브랜치 보호 규칙 설정 — 사용자가 웹 UI로 하거나, `gh` 설치 후 Claude가 대신 설정.

Claude가 작성/커밋할 것: 워크플로우 3종(`.github/workflows/`), `settings.py` sslmode 파라미터화.

## 7. 비목표 (YAGNI)

- 자동 머지(사람 승인 유지).
- 리뷰의 머지 차단(gating) — 자문만.
- 배포 자동화(별건, `docs/배포-플랜.md`가 다룸).
- Bedrock/Vertex 등 3P 프로바이더 경로 — 구독 토큰만.

## 8. 열린 리스크 / 확인 필요

- **서버 테스트가 CI Postgres에서 통과하는지**는 실제 실행으로 검증 필요(마이그레이션·시드 의존성). 최초 도입 시 실패하면 필요한 env/시드 스텝 보강.
- 자동 수정 루프의 토큰 소비 — `--max-turns` 상한과 concurrency로 억제하되, 실사용 후 관찰.
- 구독 OAuth 토큰의 GitHub Actions 사용은 구독 한도 내에서 동작(대량 병렬 시 한도 주의).
