# 일본어 번역 기능 설계 (온디바이스 무료 버전)

작성일: 2026-07-20
상태: 설계 확정 대기 (브레인스토밍 산출물)

## 1. 목적 / 한 줄 요약

일본어(단어·한자·문장)를 **카메라로 촬영하거나 사진에서 범위를 골라** OCR로 읽어들이고,
**온디바이스로 무료 번역**해 원문과 한국어 뜻을 보여주는 기능. 서버·비용·API 키 없음.

## 2. 확정된 요구사항

- 입력 방식 (둘 다 v1에 포함)
  - ① 카메라 촬영 — 촬영 후 결과 방식 (실시간 오버레이 아님)
  - ② 사진 업로드 + 범위 선택 — 갤러리에서 고른 뒤 사각형으로 잘라 그 부분만 번역
- 처리: **온디바이스**. OCR·번역 모두 기기 안에서. 인터넷 없어도 동작(모델 1회 다운로드 후), 돈 안 나감
- 결과 페이지: **원문(수정 가능) + 한국어 번역**, 전체 통번역
- **발음/후리가나 표시 안 함** (형태소 분석기 불필요 → 구현 단순화)
- 대상: 단어·한자 하나도, 문장·구절도. OCR 텍스트를 그대로 번역기에 넘기면 둘 다 자연 처리됨

## 3. 기술 스택 (신규 의존성)

| 역할 | 라이브러리 | 비고 |
|---|---|---|
| 카메라 촬영 + 갤러리 선택 | `react-native-image-picker` | 하나로 두 입력 모두 처리 |
| 범위 선택(crop) | `react-native-image-crop-picker` 내장 크롭 화면 | 사진 고른 뒤 사각형 crop. 커스텀 오버레이보다 작업량 훨씬 적음 |
| OCR (일본어) | `@react-native-ml-kit/text-recognition` | 일본어 스크립트 모델, 무료·오프라인 |
| 번역 (JA→KO) | `@react-native-ml-kit/translate` | 온디바이스, 무료·오프라인 |

### ⚠️ RN 0.86 신아키텍처 호환성 리스크

위 ML Kit 커뮤니티 라이브러리들의 신아키텍처(RN 0.86) 호환 여부는
**구현 계획 0단계(호환성 스파이크)에서 반드시 먼저 검증**한다.

- 잘 되면: 그대로 진행
- 안 되면 대안: `apps/mobile/android/` 의 Kotlin 쪽에서 Google ML Kit SDK를
  얇은 네이티브 모듈로 직접 감싼다(작업량 늘지만 확실). CLAUDE.md 2차 계획의
  네이티브 모듈 방향과 일관됨.

## 4. 화면 흐름

```
JapaneseTranslateScreen (진입)
  ├─ [카메라로 촬영] → image-picker(camera) ───────────────┐
  └─ [사진에서 선택] → image-picker(gallery) → crop(범위선택) ─┤
                                                             ▼
                                          (OCR 진행 로딩)
                                                             ▼
                                    TranslateResultScreen (결과)
                                      - 원문 텍스트 (편집 가능)
                                      - [다시 번역] (원문 수정 시)
                                      - 한국어 번역
                                      - [다시 촬영] / [완료]
```

- 카메라 경로: crop 건너뛰고 바로 OCR (전체 촬영본)
- 사진 경로: crop 후 잘린 이미지로 OCR

## 5. 컴포넌트 / 모듈 분리

- `JapaneseTranslateScreen` — 진입점. 촬영/사진선택 두 버튼. **현재 스텁 화면 대체**
- `TranslateResultScreen` — 결과. 원문 편집 + 번역 표시
- `src/features/translate/ocr.ts` — 이미지 URI → 일본어 텍스트 (ML Kit 래핑, 화면과 분리)
- `src/features/translate/translate.ts` — 일본어 텍스트 → 한국어 (모델 다운로드 관리 포함)
- 네비게이션: `TranslateResult` 라우트 추가 (`navigation/types.ts`, `navigation/MainStack.tsx`)

각 모듈은 단일 책임: 화면은 UI/상태, `ocr.ts`/`translate.ts`는 순수 변환 함수로
독립 테스트·교체 가능(추후 서버 번역으로 갈아끼울 때 `translate.ts`만 교체).

## 6. 데이터 흐름 / 상태

- 첫 번역 시 ML Kit이 **일본어·한국어 언어 모델(각 ~30MB)을 1회 다운로드** → 이후 완전 오프라인
- 첫 실행 시 "번역 모델 준비 중" 상태 표시 필요
- OCR·번역은 async. 로딩 상태는 화면 로컬 state로 충분 (서버 호출이 아니므로 React Query 불필요)

## 7. 에러 처리 (문구는 앱 톤 = 사과 없이, 다음 행동 안내)

- 카메라/갤러리 **권한 거부** → 설정 유도 안내
- **글자 인식 실패**(텍스트 없음) → "일본어 글자를 찾지 못했어요. 더 또렷하게 다시 찍어 주세요."
- **모델 다운로드 실패**(네트워크 없는 첫 실행) → 재시도 버튼
- 일본어 아닌 글자만 있을 때 → 그대로 번역 시도(무해)

## 8. 범위 / 비범위

- v1: 위 전부 (카메라 + 사진범위선택 + OCR + 온디바이스 번역 + 결과 편집/재번역)
- 비범위(추후):
  - 발음/후리가나
  - 실시간 카메라 오버레이
  - 글자 위 인플레이스(제자리) 번역 표시
  - 서버 번역 고품질 버전 (`translate.ts`만 교체하면 됨)
  - 번역 결과를 단어장/북마크로 저장

## 9. 미해결/확인 필요

- 범위 선택을 crop-picker 내장 화면으로 할지, 앱 디자인에 맞춘 커스텀 오버레이로 할지 (현재안: 내장 화면)
- RN 0.86 호환성 스파이크 결과에 따라 스택 대안 여부 확정
