# 디자인 시스템 원칙 — "AI 디자인 냄새" 회피

> 이 문서는 JapaVoca UI 작업의 **상위 규칙**이다. 개별 화면 디자인은 나중에 또 바뀔 수 있으니,
> **구조/버그를 먼저 단단히** 잡고 그 위에서 디자인 시스템을 절제 있게 다듬는다.
> 색·간격·라운드·타이포는 `apps/mobile/src/theme/tokens.ts` 단일 소스만 사용(하드코딩 금지).

## 중요! : 실제 디자이너가 만든것 같은 디자인을 해야한다 AI 가 만든것 같은 디자인을 지양한다. 

## 1. 피해야 할 AI 디자인 냄새 (체크리스트)

1. **색을 거의 하나만 쓰기 — 가장 중요.**
   - 메인이 민트라고 **글자·카드·아이콘·버튼까지 전부 민트**로 칠하지 않는다.
   - 토스/배민도 메인 컬러는 민트·파랑이지만, 글자·카드·보조 요소엔 **중립 그레이/검정**을 적절히 섞는다.
   - **글자색 기본 = 검정**(`text-primary` = gray[900]). 민트 글자는 *활성/선택 상태*나 *주액션 라벨* 같은 **기능적 위치에만**.
   - 민트는 "강조"가 아니라 **기능 신호**다: 주액션·활성 탭·선택됨. 장식으로 쓰지 않는다.

2. **8px grid에 집착하지 않기.** 4/8 배수에 기계적으로 맞추지 말고 눈에 맞는 간격을 쓴다.

3. **너무 완벽한(=사람이 안 만든 것 같은) 마감 지양.** 과하게 균일·대칭이면 오히려 인공적이다.

4. **카드 UI 남용 금지.** 정보는 카드 박스 대신 **텍스트 + spacing + subtle line(헤어라인 구분선)**으로.
   카드는 hero/주액션 진입처럼 **정당한 곳에만**.
   - (적용됨) 홈 "오늘의 학습 현황" → 구분선 인라인 통계, 지갑 거래내역 → 풀폭 구분선 리스트.
   - 설정 → `ListSection`/`ListRow`(풀폭 면 + 헤어라인 + `>`).

5. **micro-interaction는 목적 있는 곳에만.**
   - 버튼 = 즉각 반응(press scale/opacity).
   - 리스트 행 = 거의 없음(눌림 피드백 정도만).
   - **중요한 상태 변화**(보상 공개, 정답/오답)에만 애니메이션.
   - 모든 곳에 비슷한 인터랙션을 깔지 않는다.

6. **한자·일본어 글자를 "장식/배경 모티프"로 깔지 않는다. — ㅈㄴ 촌스럽다(사용자 확정).**
   - 큰 한자(예: `訳`)를 히어로 뒤 워터마크로 깐다든지, 일본어 글자를 배경 그래픽으로 쓰는 것 전부 금지.
   - 일본어 앱이라고 일본어 글자를 장식으로 쓰면 오히려 싸구려·AI스럽게 보인다. 콘텐츠(문제·번역 결과)로서의 일본어만 노출한다.
   - 화면 정체성은 **레이아웃·여백·위계**로 낸다. 배경 모티프로 때우지 않는다.

## 2. 색 역할(Color Roles) — 무엇을 위한 색인가

| 역할 | 토큰 | 쓰는 곳 | 쓰면 안 되는 곳 |
|---|---|---|---|
| 본문/제목 글자 | `text-primary`(검정), `text-secondary/tertiary`(그레이) | 대부분의 텍스트 | — |
| 브랜드 민트 | `brand` / `bg-brand` | 주액션 버튼, 활성 탭, 선택 상태, 캐시 hero 면 | 일반 글자색, 장식 아이콘, 일반 카드 |
| 옐로/앰버 | `amber` | 캐시·코인·리워드·스트릭 | 그 외 |
| 위험/감소 | `danger` | 로그아웃, 캐시 사용(−), 오답 | 일반 강조 |
| 중립 그레이 | `text-*`, `border-*`, `bg-*` | 아이콘 기본·구분선·면·보조정보 | — |

**원칙:** 한 화면에서 민트가 2~3곳을 넘으면 과하다고 보고 점검한다. 아이콘 기본색은 **중립 그레이**, 민트는 의미 있는 곳만.

## 3. 토스트 & 네트워크 오류 알림

> 짧은 안내(네트워크 끊김·전송 성공/실패 등)는 **Alert 다이얼로그가 아니라 공용 Toast**로.
> 컴포넌트: `components/Toast.tsx`. 화면 하단에서 떠올랐다가 기본 2.5초 뒤 사라진다.

### 언제 무엇을 쓰나
| 상황 | UI | 이유 |
|---|---|---|
| 네트워크 끊김(서버 무응답) | **Toast (retrying → error)** | 재시도 과정을 보여주고, 실패하면 "다시 시도" |
| 문의 전송·삭제 성공/실패 등 짧은 피드백 | **Toast (info / error)** | 흐름을 막지 않는 가벼운 안내 |
| 사용자가 반드시 확인/선택해야 하는 실패(교환 실패, 로그인 실패, 삭제 확인 등) | **`Alert.alert` / `ConfirmSheet`** | 놓치면 안 되는 결정 — 토스트로 흘려보내지 않는다 |

### 생김새 (2026-08-03 개편 — 인버스 서피스 바)
- **그림자 없음.** 면을 배경과 **반대 밝기**(라이트=잉크 `text-primary` / 다크=밝은 면)로 깔면 대비만으로 떠 보인다. 구 디자인(흰 카드)은 배경과 색이 같아 테두리 + 그림자를 겹쳐 써야 했고 그래서 무겁고 지저분했다. **대비가 할 일을 그림자에 시키지 않는다.** (사용자 확정: 그림자 X)
- **테두리도 없음.** 라운드 `radius.lg`(16), 글자 = `bg-primary`(면의 자동 대비).
- 상태는 **좌측 점 하나**로만. 인버스 면 위에서 아웃라인 아이콘은 뭉개진다.
  ⚠️ 점·액션 색은 **면 밝기에 맞춰 뒤집는다**(`inverseColors()`) — 잉크 면 위엔 밝은 단계(red400/mint300), 밝은 면 위엔 진한 단계(red500/mint600). semantic 토큰을 그대로 쓰면 앱 배경 기준이라 대비가 무너진다.
- **바는 하나다.** 새 토스트가 겹쳐 뜨지 않고 **내용만 바꿔 낀다** — "연결을 다시 시도하는 중… → 인터넷에 연결되지 않았어요"가 한 자리에서 이어지도록. (그래서 `key={message}`로 리마운트시키던 방식을 버렸다.)
- 등장 200ms / 퇴장 150ms. 퇴장 애니메이션이 끝난 뒤에 페이로드를 버린다(바로 버리면 툭 끊긴다).

### 구성
- **`ToastView`** — 순수 표시용. `visible`을 내리면 사라지고 `onHidden`을 부른다. RN `<Modal>` 위처럼 루트 토스트가 못 덮는 곳에서 직접 렌더.
- **`ToastProvider`** — 앱 루트(`App.tsx`, ThemeProvider 안)에 **한 번**. `toastBus` 단일 리스너로 등록.
- **`useToast()`** — 화면에서 `{ showToast(msg, variant?), showNetworkError() }`.
- variant 3종: `info`(완료·성공) / `error`(실패) / `retrying`(진행 중 — 스스로 안 사라지고, 아래에 좌우로 훑는 2px 불확정 진행선).

### 네트워크 오류 — 재시도가 **보이게**
- 재시도(약 2.4초, `api/retry.ts`)는 원래부터 하고 있었는데 **끝난 뒤에야** 토스트가 떠서, 사용자에겐 "시도도 안 하고 바로 실패했다"로 보였다(피드백 체크리스트 E). 그래서 재시도가 **시작될 때** 진행 중 토스트를 띄우고 결과로 교체한다.
- `api/retryNotice.ts` — `beginNetworkRetry()` / `endNetworkRetry(ok)`. 동시에 여러 요청이 재시도해도 바가 껌뻑이지 않도록 **카운터로 묶는다**(처음 하나가 시작할 때만 띄우고, 마지막 하나가 끝날 때만 결과). 하나라도 실패하면 실패로 본다 — 일부만 살아나도 화면엔 빈 자리가 남는다.
  ⚠️ begin/end는 **재시도를 시작한 요청당 정확히 한 쌍**. `client.ts`에서 `attempt === 0`인 최초 진입에서만 짝을 만든다(재시도는 재귀라 중간 시도마다 부르면 안 된다).
- **"다시 시도" 액션**: 토스트는 어떤 요청이 실패했는지 모른다. 무엇을 다시 부를지는 api 레이어가 정해 `setNetworkRetryAction()`으로 한 번 등록한다(`queryClient.refetchQueries({ type: 'active' })`).
  ⚠️ **쿼리(GET)만** 다시 부른다. 실패한 mutation을 자동 재실행하면 캐시 적립·상자 개봉이 중복될 수 있다(CLAUDE.md 캐시 정합성).
- **React Query** 캐시 레벨(`api/queryClient.ts` onError)에서 **네트워크 끊김만** 잡아 자동으로 띄운다 → 화면마다 `try/catch` 불필요. 판별은 `api/errors.ts`의 `isNetworkError()`.
- **재시도 정책**: 멱등한 GET만. 서버가 응답한 4xx/5xx와 타임아웃은 재시도하지 않는다(캐시 정합성 · 대기 시간 곱셈 방지).
- **비-React 코드 ↔ Provider 다리**: `lib/toastBus.ts`(모듈 싱글턴). 공용 문구 `NETWORK_ERROR_MESSAGE`/`NETWORK_RETRYING_MESSAGE`도 여기 한 곳에서만 정의(화면마다 하드코딩 금지).
- **예외 — RN `<Modal>` 안**: RN Modal은 별도 네이티브 윈도우라 루트 `ToastProvider`가 못 덮는다. 그런 화면(예: `QuizReviewModal`)은 `ToastView`를 모달 안에서 직접 렌더한다. `LockQuizScreen`도 직접 호출을 쓰므로 catch에서 `showNetworkError()`를 수동 호출.

### 문구 규칙 (2026-08-03 통일)
토스트는 **한 줄**이다. 30여 곳에 흩어져 있던 문구를 한 목소리로 맞췄다.
- 단문은 **마침표·느낌표 없음**. 두 문장일 때만 사이에 마침표.
- **"잠시 후"를 쓰지 않는다** — 언제 되는지 모르면서 아는 척이다.
- **"다시 시도해주세요"를 쓰지 않는다** — 버튼이 바로 옆에 있는데 말로 시키지 않는다. 고치는 방법이 자명하지 않을 때만 안내 문장을 남긴다(`지갑에서 확인해주세요` · `다시 로그인해주세요` · `다른 사진을 골라주세요`).
- **캐시(돈)에 관한 사실은 지우지 않는다.** 예: `광고 확인이 지연되고 있어요. 캐시는 차감되지 않았어요`.
- 실패는 `~하지 못했어요`로 통일(`~에 실패했어요` 폐기).
- ⚠️ 제목(무슨 일이 났는지)과 안내(어떻게 고치는지)를 나눠 든 곳은 **토스트에 제목부터** 넣는다. 번역 오류가 `errorMessage().message`만 넘겨서 "다른 사진으로 다시 시도해 주세요"라는 지시문만 뜨고 정작 무슨 일이 났는지가 빠져 있었다 → `toastText()` 신설.

**2026-08-03 캐시 내역·알림 리디자인** (frontend-design):
- **행마다 반복되는 색 칩을 걷어냈다** — 캐시 내역의 초록/빨강 원형 아이콘 제거. §1.1의 연장선:
  기능색이라도 **매 줄 반복되면 신호가 아니라 벽지**가 된다. 적립/사용은 부호 + 금액 색으로 충분.
  반대로 알림은 칩을 **남겼다** — 거기선 종류(상자/교환/문의)가 실제 정보다. 대신 칩 **색**은
  종류가 아니라 **읽음 여부**만 말한다(종류마다 색을 칠하면 장식).
- **캐시 내역 시그니처 = 잔액 열**: 금액 아래 거래 후 잔액(`balance_after`)을 세워 통장처럼
  읽히게. 돈 화면의 신뢰는 "잔액이 흐르는 게 보이는가"에서 온다. 장식이 아니라 이미 있는 데이터.
- 요약 블록은 카드 없이 텍스트 + 헤어라인(§1.4), 필터는 알약 칩이 아니라 **밑줄 탭** — 목록의
  헤어라인 언어와 같은 결. 민트는 활성 밑줄 한 곳에만(§2).
- 신규 공용 컴포넌트: `LogSectionHeader`(면 색을 행과 같게 둬 sticky에도 회색 띠가 안 생김),
  `EmptyState`(아이콘을 원형 칩에 가두지 않는다 — 없는 데이터에 무게를 싣지 않는다. 빈 화면은
  안내가 아니라 **다음 행동**을 준다).
